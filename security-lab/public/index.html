SQL Injection Prevention

  • Use Parameterized Queries - Never concatenate user input into SQL
  • Input Validation - Whitelist allowed characters
  • Least Privilege - Database user should have minimal permissions
  • Error Handling - Don't expose database errors to users

Vulnerable Code:

// ❌ VULNERABLE
const query = `SELECT * FROM users 
  WHERE username = '${username}'`;

Secure Code:

// ✅ SECURE
const user = db.prepare(
  'SELECT * FROM users WHERE username = ?'
).get(username);

XSS Prevention

  • Output Encoding - Escape HTML entities before rendering
  • Content Security Policy - Restrict script sources
  • HttpOnly Cookies - Prevent JavaScript access to cookies
  • Input Validation - Sanitize user input

Types of XSS:

  • Reflected - Payload in URL/request
  • Stored - Payload saved in database
  • DOM-based - Payload manipulates DOM

Defense in Depth

  • Security Headers - CSP, X-Frame-Options, etc.
  • Rate Limiting - Prevent brute force attacks
  • Logging & Monitoring - Detect attacks early
  • Input Validation - Validate all user input
  • Authentication - Strong password policies, MFA
  • Authorization - Proper access controls
  • HTTPS - Encrypt data in transit
  • Regular Updates - Patch vulnerabilities
